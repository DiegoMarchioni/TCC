Os dois mecanismos no código do trabalho

Mônadas · Monadic.hs (trecho)

type Env = Map String Int
type Interp a =
  ExceptT String (StateT Env IO) a

eval (Var x) = do
  env <- get
  maybe (throwError (msgUnbound x)) return
        (Map.lookup x env)

Cada efeito é uma camada da pilha, e o tipo diz quais existem. get lê o estado e throwError lança o erro.

Efeitos · interp_effects.ml (trecho)

type _ Effect.t +=
  | Get : string -> int option Effect.t
  | Set : string * int -> unit Effect.t
  | Fail : string -> 'a Effect.t
  | Output : int -> unit Effect.t

(* handler de estado, em run_state *)
| Get x -> Some (fun k ->
    continue k (Hashtbl.find_opt tbl x))

Cada efeito é uma operação declarada. O handler decide o que ela faz e retoma a computação com continue.

No Haskell, o efeito está no tipo da computação. No OCaml, está numa operação que o handler interpreta.

(1:10 · acumulado 4:10) Âncora: no Haskell o efeito está no tipo, no OCaml numa operação que o handler interpreta. Antes do método, vale ver os dois mecanismos como eles aparecem no meu código. À esquerda, o Haskell. O tipo Interp é a pilha: uma camada de exceção, sobre uma de estado, sobre IO. Na eval, o caso da variável lê o estado com get e, se a variável não existe, lança o erro com throwError. O efeito está no tipo da função. À direita, o OCaml. Primeiro eu declaro as operações: Get, Set, Fail e Output. Embaixo está o handler de estado. Quando o código pede Get, ele procura a variável na tabela e retoma a computação com continue, entregando o valor. A diferença central é esta: no Haskell, quem decide o efeito é o tipo. No OCaml, é quem trata a operação. [Aponte o tipo Interp ao falar da pilha e a linha do continue ao falar do handler.]
